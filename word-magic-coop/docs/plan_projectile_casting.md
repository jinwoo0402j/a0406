# 구현 플랜: 모든 마법을 투사체로 + 조합·시전 매끄럽게 (검토 반영판)

> 코드는 고치지 않았습니다. 이미 있는 파일·함수 이름은 직접 열어서 확인한 것만 적었습니다. 새로 만들 이름에는 **(새)**를 붙였습니다. 수치는 모두 [임시]입니다. 사용자가 정할 칸은 **Qn**으로 표시했습니다.

**세 줄 요약**
1. 조준해서 쏘면 대상이 없어도 탄이 나가고, 실제로 맞은 것에만 효과가 납니다(M036·M029). `<수증기>` → `<불>` → `<밀치기>`(Q2 답 뒤) → `<당기기>` → `<들기>`(Q1 답 뒤) 순서로 한 단어씩 바꿉니다. 단계마다 테스트가 모두 통과한 상태로 끝냅니다.
2. 조합→시전 흐름(M040)은 결정 없이 고칠 수 있는 표시부터 고칩니다. 다음 두 가지는 사용자 답을 받은 뒤에 합니다.
   - 새 효과 단어가 손에 들렸다가 바로 내려가는 문제(Q20)
   - 창을 열지 않고 수식 붙이기(Q13)
3. 결정은 `docs/design_additions.md`에 출처를 나눠 적고(사용자 원문 / assistant 제안 / [임시]), 문서 머리말도 그에 맞게 고칩니다. 아직 정하지 않은 20가지는 질문으로 남깁니다.

### 0-3. 지금 코드와 다른 점
- 조준 모드에서 탄으로 나가는 것은 `<파이어볼>`·`<물>`뿐입니다(`CAST`, server/spells.js:15-31).
  - `castPush`·`castPull`·`castFire`·`castSteam`과 `startLift`(server/lift.js:13)는 `resolveTargets`로 조준선에서 대상을 고릅니다. 대상이 없거나 적용할 수 없으면 `fail(res.reason)`으로 `castFail`을 보냅니다.
  - 주변 모드도 반경 안에 곧바로 적용됩니다.
- 조준점과 미리보기가 "못 쓴다"는 경고로 쓰이고 있습니다(client/main.js `updateHud`, client/preview.js `buildPreview`).
- 수식을 붙여 쏘는 가장 짧은 길은 E → Shift+클릭 → E → 클릭입니다.
  - 입력 4번, 창 전환 2번이 필요합니다. 그동안 마우스 잠금이 풀리고 이동이 멈춥니다.
  - 섞은 뒤 쏘려면 입력이 9번쯤 필요합니다.
- 줍기에서 서버와 화면이 어긋납니다.
  - 서버 `receiveToken`(server/tokens.js:41-45)은 손이 비면 새 효과 단어를 손에 쥐여 줍니다.
  - 화면 `Inventory.add`는 마인크래프트 순서대로 첫 빈칸에 넣습니다. 고른 칸이 아니면 `Inventory.hand()`가 null이 되고, `wanted`가 `loadout{effect:null}`을 보내 되돌립니다.
  - 그래서 주울 때 말풍선에는 손 그림이 뜨는데, 실제로는 손에 없습니다. 섞은 결과(server/world.js:164)도 같습니다.
- **선후를 알 수 없는 것**: M036과 10-01 승인표(주변+들기, 주변 파이어볼 4발, 발밑 폭발) 중 어느 쪽이 먼저인지 모릅니다. 대화 내보내기 파일에 시각이 없기 때문입니다. Q3에서 확인합니다.

## 1. 바뀌는 규칙

### 1-1. 확정 규칙 (사용자 원문 기준)
- 조준 모드에서는 대상이 있든 없든 탄이 나갑니다(M036).
- 효과는 탄이 실제로 맞은 것에만, **맞는 순간의 상태**로 판정합니다(M029). 보호(R)·들림·빈 원천도 그 순간이 기준입니다. 지금 `explode`가 하는 방식과 같습니다.
- 적용 방식은 단어마다 다릅니다. `<밀치기>`는 한 번 적용되고, `<들기>`는 유지되며 우클릭으로 끝냅니다(M029·M034).
- 순서 문법은 넣지 않습니다(M040).
- 탄의 빠르기, 그리고 새 탄에서 `<큰>`이 무엇을 키우는지는 아직 정하지 않았습니다(Q2·Q19).

### 1-2. 쏘기 전에 막는 것과 맞은 뒤 결과로 옮기는 것
- **쏘기 전에 막는 것(6가지만 남김)**
  - `NO_EFFECT`
  - 모드 안 됨(`modeUnsupported`)
  - `SUSTAINING`: 들기 유지 중이거나, 들기 탄이 날아가는 중
  - `COOLDOWN`
  - `BAD_AIM`
  - `NOT_PLAYING`
- **맞은 뒤 결과로 옮기는 것**
  - `TERRAIN`, `NOT_MOVABLE`, `NOT_LIFTABLE`, `ALREADY_HELD`, `HOLDING_YOU`, `STANDING_ON`, `PROTECTED`, `NOT_HEATABLE`, `SOURCE_EMPTY`, 당기기의 "벽에 너무 가까움"
- **없어지는 것**
  - 조준 모드의 `NO_TARGET`·`OUT_OF_RANGE`는 "사거리 끝에서 사라짐(`fizzle`)"으로 바뀝니다.
- 수식은 발사 순간의 값으로 굳습니다. 지금 `spawnFireball`과 같습니다.

### 1-4. 답이 오기 전 임시 기본값
- 기본값은 새 규칙이 아니라 **"지금 `<파이어볼>`·`<물>`이 하는 방식"**만 빌립니다. 모두 [임시]로 문서에 적습니다.
  - 탄 속도: 파이어볼과 같게(14m/s). 적용 대상은 `<수증기>`·`<불>`·`<당기기>`·`<들기>`입니다. **`<밀치기>`는 넣지 않습니다.** 사용자의 "즉시 발동"(M029)과 부딪힐 수 있으므로 Q2 답 전에는 바꾸지 않습니다.
  - 대기시간은 발사할 때 시작합니다(Q7).
  - 날아가는 길의 친구도 맞습니다(Q8).
  - 효과가 없을 때는 지금 쓰는 말풍선을 그대로 씁니다(Q5).
  - 지형 당기기는 지금 규칙 그대로입니다(Q9).
  - `<큰>`은 단어마다 지금 쓰는 사거리 배율(`pushReach`·`pullReach`·`fireReach`·`steamReach`)을 그대로 씁니다(Q19). 들기는 지금처럼 곱하지 않습니다. 이 값을 테스트에 박지 않습니다.
- 이렇게 정한 이유: 이 플랜의 원칙은 "답을 기다리느라 멈추지 않되, 새 규칙을 지어내지 않는다"입니다. 그래서 이미 있는 탄의 방식만 빌립니다. M036의 "해보면서 바꾸면"은 에임 표시에 대한 말이므로 여기서는 근거로 쓰지 않습니다.

### 1-5. 데이터 표 설계 (단어 하나를 더하거나 바꿀 때 고칠 곳)

| 무엇 | 파일 | 바꾼 뒤 |
