# 단어로 만드는 마법 — 협동 마법 모험 게임 기획서

**버전:** v0.2  |  **작성일:** 2026-09-30

> 친구들과 모험하며 단어를 얻고 나눈다.
> 단어로 마법의 규칙을 만들고, 그 가능성을 함께 실험한다.

### 01  게임의 정체성

단어를 수집·교환해 주문을 구성하고, 그 주문으로 친구·사물·환경에 개입하는 협동 모험 게임이다. 캐릭터 조작과 시전은 단순하게, 주문의 활용법과 친구들의 반응은 다양하게 만든다. 전투 중심인지 탐험 중심인지는 아직 확정하지 않는다.

이 게임에서 단어는 특정 사물에만 통하는 열쇠가 아니다. 마법의 작동 규칙을 구성하는 부품이다. 같은 「대상을 띄운다」로 친구도, 돌도, 상자도 띄울 수 있어야 한다.

### 핵심 경험

| 만드는 재미 | 함께 사용하는 재미 |
| --- | --- |
| “이 단어를 붙이면 어떻게 될까?”<br>새로운 조합을 예상하고 구성한다. | “이걸로 저길 건너면 되겠는데?”<br>같은 목표에 서로 다른 방식으로 개입한다. |
| “그 단어 나도 써보자.”<br>교환을 통해 팀의 활용법이 달라진다. | “잠깐, 나까지 날아가잖아!”<br>일관된 규칙에서 사고가 생기고 함께 수습한다. |

### 기획 상태와 문서의 경계

| 구분 | 현재 기준 |
| --- | --- |
| 합의된 핵심 | 친구와의 멀티플레이, 단어 수집·조합·교환, 공통 대상 지정 규칙, 단순한 조작, 둥글고 귀여운 SD 분위기. |
| 이번 문서의 제안 | PC·3D·3인칭, 2인 프로토타입, 단어 5종, 작은 고정 공간 1개. 검증을 위한 시작안이며 최종 사양은 아니다. |
| 열어두는 결정 | 전투와 탐험의 비중, 최종 인원, 로그라이크 구조, 플랫폼·엔진, 정식 세계관과 제목. |

> 현재 대화에서 합의한 아이디어를 설계안으로 구체화한 문서다. 기능의 구현 여부나 재미가 검증되었다는 뜻은 아니다. 이전 최소안의 사물별 대상 단어는 이 문서의 공통 선택 규칙으로 대체한다.

## 플레이 경험과 반복 흐름

단어의 변화 → 마법의 변화 → 친구들과 겪는 상황의 변화

### 02  기본 플레이 흐름

> 함께 출발 → 단어 발견 → 주문 구성 → 시험·교환
> → 장애물 해결 또는 사고 발생 → 수습하며 전진 → 새로운 단어

모험은 함께 움직일 이유를 제공하고, 단어는 그 상황에 개입하는 방법을 바꾼다. 진행에 정해진 주문 하나만 요구하기보다, 이동·위치·범위가 다른 여러 해결을 허용한다. 랜덤 맵이나 전투는 이 연결을 확인한 뒤 결정한다.

### 짧은 플레이 시나리오

| 장면 | 플레이어가 겪는 일 |
| --- | --- |
| 1. 함께 출발 | A는 「대상을 민다」, B는 「대상을 띄운다」를 구성한다. 같은 주문으로 친구와 짐을 번갈아 건드리며 사용법을 익힌다. |
| 2. 새로운 단어 | 「주변의 대상들을」을 발견한다. B가 「주변의 대상들을 띄운다」로 바꾸자 짐뿐 아니라 근처의 A도 함께 떠오른다. |
| 3. 활용법 발견 | A가 “이대로 위에 보내줘”라고 한다. 둘은 우연히 생긴 상황을 이동 방법으로 바꿔본다. |
| 4. 교환과 실험 | A가 범위 단어를 넘겨받아 「주변의 대상들을 민다」를 만든다. 장애물들을 치우지만, 가까이 있던 B와 짐도 함께 밀린다. |
| 5. 조합 재선택 | 위험한 구간에서는 범위 주문 대신 「대상을 민다」로 필요한 짐 하나만 정확하게 옮긴다. 범위가 넓다고 항상 좋은 것은 아니다. |
| 6. 공동 도착 | 서로를 띄우거나 「자신을 띄운다」를 사용하며 짐과 함께 도착한다. 특정 주문 순서를 따르지 않아도 성공한다. |

### 경험을 지키는 원칙

단순한 입력, 다양한 용도: 주문을 구성한 뒤에는 한 번의 입력으로 반복 시전한다. 마법 종류가 아니라 상황과 대상에 따라 사용처가 달라지게 한다.

규칙은 예측 가능하게, 결과는 상황에 따라: 음성 인식 실패나 무작위 주문 오작동으로 웃음을 강제하지 않는다. 친구의 위치, 타이밍, 함께 적용된 마법에서 사건이 생기게 한다.

장난은 수습 가능하게: 동료에게도 효과가 적용되지만, 당하는 사람이 벗어날 수 있어야 한다. 낙하나 잘못된 조합이 긴 대기나 진행 불능으로 이어지지 않게 한다.

## 주문 문법과 대상 선택

무엇인가의 이름이 아니라, 무엇을 고를 것인가의 규칙

### 03  기본 문법

> [대상 지정 규칙] + [작용]
> 예: [대상을] + [띄운다] → 대상을 띄운다.

「친구를」「돌을」「상자를」 같은 사물별 전용 대상 단어는 기본 사전에 넣지 않는다. 실제로 무엇이 마법에 걸리는지는 시전 순간의 조준과 범위, 대상의 공통 속성으로 결정한다.

단어 토큰은 한 어절일 필요가 없다. 「주변의 대상들을」도 하나의 의미 부품이다. 플레이어가 임의의 자연어를 입력하는 방식이 아니라, 정의된 부품을 슬롯에 배치해 문장을 만든다.

### 최소 프로토타입의 대상 지정 단어 3종

| 표시 문구 / ID | 선택 규칙 | 제약 |
| --- | --- | --- |
| 대상을<br>AIMED | 조준선이 처음 맞힌 대상 1개를 선택한다. | 시전자 자신 제외. 최대 8m. 벽에 막히면 그 뒤의 대상을 찾지 않는다. |
| 자신을<br>SELF | 시전자 자신을 선택한다. | 조준과 무관하다. 외부 대상을 함께 선택하지 않는다. |
| 주변의 대상들을<br>NEARBY | 시전자 중심 반경 3m 안의 대상들을 선택한다. | 시전자 자신 제외. 벽에 가려진 대상 제외. 아군·적·사물이라는 이유로 구분하지 않는다. |

범위 기준은 시전자 위치다. 조준한 물체 주변을 뜻하지 않는다. 범위 단어는 시전 순간에 대상 목록을 한 번 확정하며, 나중에 들어온 대상에는 자동으로 효과가 생기지 않는다.

### 선택과 적용 가능 여부를 분리한다

대상 지정 규칙은 “누구를 고르는가”를 정한다. 작용은 “그 대상이 이 효과를 받을 수 있는가”를 검사한다. 움직일 수 있는 친구와 상자는 같은 규칙으로 처리하고, 고정된 지형은 움직임 효과를 받지 않게 한다.

범위 안에 유효한 대상과 무효한 대상이 섞이면 유효한 대상에만 적용한다. 아무 대상에도 적용할 수 없으면 시전되지 않은 이유를 짧게 표시한다. 숨겨진 사물별 예외보다 일관된 속성과 화면 피드백을 우선한다.

> 거리·반경은 초기 조절값이다. 대상 중심점 기준 거리와 시전자에서 대상까지의 가림 여부를 사용하되, 조준 표시와 실제 판정이 일치해야 한다.

## 작용과 공통 상호작용

선택 방식이 달라도, 효과를 적용하는 규칙은 같다

### 04  최소 프로토타입의 작용 단어 2종

| 작용 / ID | 공통 규칙 |
| --- | --- |
| 민다 / PUSH | 움직일 수 있는 대상에 수평 이동을 가한다. 방향은 시전자에서 대상 쪽이다. 자기 자신이거나 두 위치가 겹치면 카메라의 수평 전방을 사용한다. 초기 속도 변화 4m/s, 외부 수평 속도 상한 8m/s. |
| 띄운다 / LIFT | 공중 이동이 가능한 대상을 기준 높이에서 약 2m 올리고 총 3초 동안 부양시킨다. 이후 정상 중력으로 돌아간다. 수평 조작과 지형 충돌은 유지한다. |

「주변의 대상들을 민다」는 같은 방향 규칙을 여러 대상에 적용한 결과로 시전자 바깥쪽으로 퍼진다. 「자신을 민다」는 같은 규칙의 자기 대상 처리에 따라 전방 이동이 된다. 별개의 완성형 주문으로 구현하지 않는다.

### 5종의 단어로 구성하는 6가지 기본 주문

| 대상 규칙 | 민다 | 띄운다 |
| --- | --- | --- |
| 대상을 | 가리킨 친구·물체 하나를 이동시킨다. | 가리킨 친구·물체 하나를 부양시킨다. |
| 자신을 | 시전자 자신이 전방으로 이동한다. | 시전자 자신이 떠오른다. |
| 주변의 대상들을 | 근처 친구·물체들을 바깥쪽으로 민다. | 근처 친구·물체들을 함께 띄운다. |

### 마법끼리 만나면

서로 다른 효과는 함께 적용된다. 떠 있는 짐을 밀면 공중에서 수평 이동해야 한다. 새 효과가 기존 효과를 통째로 지우거나 플레이어의 이동 코드가 마법 이동을 즉시 덮어쓰면 안 된다.

같은 효과의 반복은 제한한다. 연속 밀기는 속도 상한을 따른다. 공중에서 띄우기를 반복해도 높이는 누적되지 않는다. 부양 지속시간만 갱신하며, 착지해야 새 상승 기준을 잡는다.

### 동료 장난과 복구

동료에게도 동일한 효과가 적용된다. R은 자신의 부양 상태와 외부 이동 효과를 해제하고, 다른 플레이어가 거는 이동 마법에 2초간 면역을 준다. 자기 시전은 이 면역과 구분한다. 보호 상태는 양쪽 화면에 표시한다.

낙하 시 플레이어와 목표 짐을 각자의 안전한 위치로 복구한다. 복구할 때 진행 중인 효과와 속도를 초기화한다. 무한 상승, 맵 밖 추방, 계속 붙잡아 두는 방해가 핵심 놀이를 막지 않게 한다.

> 능력은 Movable(외부 이동 가능), Floatable(부양 가능)처럼 공통 속성으로 구분한다. 최소안의 캐릭터와 이동 사물은 두 속성을 모두 가지며, 고정 지형은 가지지 않는다. 수치와 보호 규칙은 테스트 후 조절한다.

## 단어 수집·교환과 조작

단어를 넘기면 소유권뿐 아니라 팀의 가능성도 바뀐다

### 05  최초 단어 배치

| 위치 | 보유 단어 | 시작 역할 |
| --- | --- | --- |
| 플레이어 A | 대상을 + 민다 | 정밀하게 하나를 밀 수 있다. |
| 플레이어 B | 대상을 + 띄운다 | 정밀하게 하나를 띄울 수 있다. |
| 탐험 공간 | 자신을 × 1개<br>주변의 대상들을 × 1개 | 누가 보유하고 어떤 작용과 결합할지 선택한다. |

단어 종류는 대상 지정 3종과 작용 2종으로 총 5종이다. 「대상을」만 2개이므로 실제 토큰은 총 6개다. 신규 단어는 시작 지점에서 조금 이동하면 발견할 수 있게 고정 배치한다. 이번에는 무작위 획득을 넣지 않는다.

### 소유와 교환

단어는 개인 소유이며 팀 공용 해금이 아니다. 각 토큰은 고유 ID를 가지고 월드 또는 한 사람의 인벤토리 중 한 곳에만 존재한다. 가까이 있는 단어를 주워 소유하고, 인벤토리에서 내려놓으면 다른 사람이 가져갈 수 있다.

장착한 단어를 넘기면 해당 슬롯이 비고 이전 소유자는 그 주문을 새로 시전할 수 없다. 이미 발동한 효과는 원래 지속시간까지 유지한다. 최소안에는 단어 소모, 인벤토리 용량 제한, 거래 승인창을 넣지 않는다.

교환의 목적은 문을 열 열쇠를 전달하는 데 그치지 않는다. B가 범위 단어로 함께 띄우기를 시험한 뒤 A에게 넘기면, A는 같은 단어로 함께 밀기를 시험할 수 있다. 교환 없이도 진행할 수 있지만, 교환하면 다른 방법이 열리는 상황을 만든다.

### 문장 편집과 시전

| 입력 | 기능 |
| --- | --- |
| WASD / 마우스 / Space | 이동 / 시점과 조준 / 점프 |
| Tab | 인벤토리와 두 슬롯 편집. 보유한 대상 지정 단어와 작용 단어를 선택한다. |
| 좌클릭 / E / R | 현재 문장 시전 / 가까운 단어 줍기 / 자신에게 걸린 이동 효과 해제 |

플레이어당 활성 주문은 1개다. 편집 후 버튼 한 번으로 반복 시전하며 매번 문장을 입력하지 않는다. 편집창을 열면 카메라 회전과 시전을 막는다. 정상 시전의 재사용 대기시간은 초기 1초이며, 마나 비용은 없다.

HUD는 현재 문장, 적용 가능한 대상 표시, 대기시간, 단어 획득·소유 안내를 보여준다. 범위 주문은 적용 가능한 대상들을 미리 강조해 친구가 함께 걸린다는 사실을 알아볼 수 있게 한다. 잘못된 조합이나 무효 대상은 대기시간을 소비하지 않는다.

## 최소 제작 범위와 테스트 공간

상자 운반은 테스트 과제이며, 최종 게임 장르가 아니다

### 06  최소 프로토타입 제안

| 항목 | 이번 범위 |
| --- | --- |
| 실행과 인원 | PC, 3D, 3인칭, 실제 네트워크로 접속하는 정확히 2명. 기존 프로젝트가 있으면 그 환경을 우선한다. |

### 하나의 작은 공간에 세 상황을 배치한다

| 구역 | 시험할 행동 |
| --- | --- |
| 출발·연습 구역 | 낙하 위험이 없는 바닥에서 친구·돌·상자를 같은 주문으로 번갈아 건드린다. 사물별 주문 변경이 필요 없어야 한다. |
| 발견·실험 구역 | 새 대상 지정 단어 2개를 발견한다. 사물들이 모인 곳에서 정밀 주문과 범위 주문을 비교하고, 단어를 넘겨 다른 작용과 결합한다. |
| 도착 구역 | 부양으로 넘을 수 있는 낮은 단차와 짐 운반 상황을 둔다. 개별 운반·범위 부양·자기 이동을 섞어 다양한 순서로 도착하게 한다. |

높이와 거리는 실제 이동·마법 수치에 맞춰 조정한다. 단순 점프로 모든 과제를 무시하게 만들지는 않되, 특정 주문 하나만 인정하는 문이나 스크립트 정답도 두지 않는다. 물체 위에 서기와 함께 이동하는 기본 충돌을 지원한다.

### 이번에 구현하지 않는다

적·전투·체력, 로그라이크 성장과 영구 해금, 절차적 맵, 상점·희귀도, 음성 인식·자유 문장 입력·LLM 해석, 긴 문장·수식어·조건문, 3인 이상, 정식 모델·래그돌·파괴 물리, 인터넷 매칭·Steam 초대·릴레이, 저장과 진행 중 재접속.

> 대상 지정 × 작용만으로 시작한다. 수식어는 필수가 아니다. 새 단어가 기존 작용의 사용법을 바꾸는지 먼저 확인한 뒤, 필요할 때 「반복해서」「잠시 뒤에」 같은 확장 규칙을 별도로 설계한다.

## 구현 원칙과 기능 완료 기준

범용 자연어 엔진이 아니라, 작은 규칙 조합 시스템

### 07  처리 구조

> 보유 단어 확인 → 대상 지정 규칙으로 대상 목록 결정
> → 대상별 공통 속성·보호 상태 검사 → 작용 적용 → 결과 동기화

대상 선택과 효과 적용을 분리한다. 단어는 ID·표시명·슬롯 분류·선택 규칙 ID 또는 작용 ID로 정의한다. 문장은 두 토큰을 참조한다. 여섯 문장을 각각 별개의 완성형 스킬로 하드코딩하지 않는다. 범용 스크립트 언어나 노드 에디터도 만들지 않는다.

### 멀티플레이와 상태

처음부터 호스트와 게스트가 접속해 각자 조작하는 뼈대로 시작한다. 같은 PC의 두 프로세스 또는 같은 로컬 네트워크에서 테스트한다. 인터넷 자동 연결이나 원거리 초대가 된다고 설명하지 않는다.

호스트가 토큰 소유권, 획득·드롭, 주문 유효성, 효과, 사물 위치와 클리어를 확정한다. 게스트는 요청을 보내고 결과를 반영한다. 자기 시전과 게스트 시전에 같은 검증을 적용한다. 동시에 주워도 토큰이 복제되거나 사라지면 안 된다.

낙하한 단어는 안전 지점으로 돌아온다. 플레이어 낙하 시 보유 단어는 유지한다. 재시작은 위치·소유권·슬롯·효과·대기시간을 최초 상태로 되돌린다. 연결이 끊기면 안내 후 로비로 돌아가며 호스트 이전은 제외한다.

## 재미 검증과 제작 인계

기능이 작동하는 것과, 다시 조합하고 싶은 것은 별개다

### 08  플레이테스트에서 볼 것

| 관찰할 장면 | 잘 나오지 않으면 |
| --- | --- |
| 같은 주문을 친구뿐 아니라 다른 사물에도 자발적으로 사용한다. | 대상 표시, 작용의 일관성, 효과를 알아보기 쉬운 피드백부터 고친다. |
| 새 단어를 얻고 “이거 붙이면?” 하며 기존 주문을 바꿔본다. | 새 단어의 결과가 실제 행동을 바꾸는지 확인한다. 단순 숫자 차이나 메뉴 선택으로만 남기지 않는다. |
| 다른 조합을 쓰려고 단어를 부탁하거나 넘긴다. | 교환을 의무로 만들기보다, 같은 단어를 다른 작용과 결합할 이유를 만든다. |
| 정밀·자기·범위 선택 중 상황에 맞는 것을 고른다. | 항상 유리한 조합이 있는지, 범위 변화의 이득과 사고 가능성이 드러나는지 본다. |
| 실수를 이해하고 수습하거나 다른 방법을 시도한다. | 입력 실패·긴 복구·일방적인 방해가 재미를 막는지 먼저 고친다. |

고정된 마법 버튼으로 바꿔도 경험이 거의 같다면, 단어 조합이 아직 핵심 재미로 작동하지 않는 것이다. 이때는 단어 수를 늘리기 전에 조합 선택과 교환의 의미를 손본다. 위 행동들은 관찰 기준이며 재미를 보장하는 수치 지표가 아니다.

### 다음 확장 순서

기본 상호작용 확인 → 새로운 작용 1종의 여러 용도 확인 → 수식어 필요성 판단 → 모험 목표와 반복 구조 선택. 전투, 랜덤 획득, 절차적 맵은 한꺼번에 추가하지 않는다. 최종 장르는 실제로 재미있는 사용 장면을 보고 결정한다.

### 클로드에게 전달할 작업 지시

> 이 문서의 최소 프로토타입을 실행 가능한 프로젝트로 구현해줘.
> 핵심은 「대상 지정 규칙 × 작용」이며, 사물별 전용 주문으로 바꾸지 마.
> 같은 주문을 친구·돌·상자에 공통으로 사용하고, 단어 교환에 따라 구성 가능한 마법이 달라져야 해.

기존 프로젝트가 있으면 해당 엔진·언어·구조를 따른다. 없다면 접근 가능한 환경을 확인해 사용할 엔진과 버전을 명시한다. 미정인 최종 장르나 확장 기능을 임의로 구현하지 않는다.

구현 순서는 ① 두 클라이언트 접속·이동 ② 공통 대상 선택과 밀기·띄우기 ③ 단어 소유·편집·교환 ④ 작은 테스트 공간·복구·클리어 ⑤ T1~T7 검증으로 한다. 각 단계에서 실행 가능한 상태를 유지한다.

전체 프로젝트, 실행·접속 방법, 조작법, 조절 가능한 수치, 실제 수행한 테스트와 알려진 문제를 제출한다. 실행하지 못한 항목은 미검증으로 표시한다. 새로운 요구사항이 필요하면 구현 편의를 위해 핵심 경험을 바꾸지 말고 그 이유와 최소 대안을 명시한다.

> 출발점: 단어로 만든 가능성을 친구들과 실험하는 게임. 제작 규모는 줄여도, “조합이 달라지면 행동과 상황이 달라진다”는 연결은 남긴다.
