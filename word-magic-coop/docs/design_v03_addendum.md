## 01  캐릭터와 모험의 구성

예측 가능한 규칙 속에서, 친구들의 행동이 웃긴 사건을 만든다.

### 캐릭터: 귀여움 또는 병맛, 형태까지 과장

실사풍이나 화려한 그래픽 자체를 목표로 하지 않는다. 캐릭터는 **귀엽거나 우스꽝스러운 인상**을 가져야 한다. 행동 시 팔다리의 동작 범위만 크게 하는 것이 아니라, 얼굴·신체 등 **모델의 형태 자체가 과장되게 변하는 느낌**을 지향한다.

> 사용자 지정 레퍼런스 — **Big Walk**
> 마이크 음량이 클수록 입이 커지고, 말할 때마다 입이 돌출되는 표현. 행동의 세기와 리듬이 눈에 보이는 변형으로 나타나는 점을 참고한다.

**참고·경계:** 위 내용은 사용자가 설명한 참고 장면이다. 이 언급만으로 음성 인식 주문이나 음성 채팅 기능의 구현을 확정하지 않는다. 음량 반응 기능을 직접 도입할지, 마법 동작에 유사한 변형을 적용할지는 별도 결정한다.

### 진행: 모험이 주가 되고 전투·휴식이 섞인다

| 구성 | 현재 방향 |
| --- | --- |
| 모험·퍼즐 | 플레이의 중심. 함께 이동하고 단어를 발견·조합·교환하며 여러 방법으로 상황을 해결한다. |
| 전투 | 플레이어들이 조작에 익숙해지고 단어를 어느 정도 얻은 뒤 한 번씩 등장한다. 간단한 전투와 보스형 전투 모두 구상한다. |
| 휴식 | 상점이나 이벤트 등 다른 종류의 상황을 뜻한다. 반드시 체력 회복 구역이나 전투 뒤의 고정 단계라는 뜻은 아니다. |

세 요소의 **고정 순서·비율·등장 횟수는 미정**이다. 모든 구역에 보스를 넣거나 모험→전투→휴식을 일정 간격으로 반복하도록 확정하지 않는다.

### 월드: 큰 구역 안에서 끊기지 않는 이동

하나의 큰 맵을 이동하며 즐기는 **연속형 오픈월드**를 지향한다. 같은 큰 모험 구역 안에서 이동할 때마다 로딩 화면이 뜨는 구성은 피한다. 다른 환경으로 넘어가는 등 큰 모험 단위가 끝나는 시점에는 로딩을 허용한다.

맵 크기·구역 수·연결 방식은 개발하면서 조정한다. 월드 전체의 완전 무로딩, 특정 스트리밍 기술, 절차적 생성이나 로그라이크 진행은 이번에 확정한 요구가 아니다.

## 02  주문 구성과 대상 모드

무엇을 쓸지는 단어로, 누구에게 쓸지는 조작으로 정한다.

> **주문 = 효과 단어 + 수식 단어의 조합**
> **대상 선택 = 주문과 별개인 전환 모드**

### 대상 지정 단어를 완전히 제거한다

기존의 `<대상을>`, `<자신을>`, `<주변의 대상들을>`은 더 이상 수집·교환·장착하는 단어가 아니다. 대상 선택을 위한 단어 슬롯과 드롭 아이템도 제거한다. 대상 모드를 바꾸기 위해 단어를 얻거나 친구에게 빌릴 필요가 없어야 한다.

| 대상 모드 | 기본 의미 | 남아 있는 결정 |
| --- | --- | --- |
| 조준 대상<br>기본 모드 | 내가 조준하는 쪽의 대상에 마법을 사용한다. 투사체형은 실제 명중한 대상에 적용 판정한다. | 사거리, 조준 보정, 효과별 유효 대상 조건. |
| 본인 | 시전자 자신을 향한 사용 모드로 전환한다. | 각 효과의 자기 적용 방식. 특히 들기·파이어볼의 동작. |
| 주변 | 주변에 적용하는 사용 모드로 전환한다. | 범위 중심·반경·자신 포함 여부·벽 차단·선정 시점. |

전환 버튼으로 모드를 바꾼다. 키 배치와 전환 순서는 미정이다. 같은 효과가 친구·적·사물에 공통으로 작동한다는 원칙은 유지하며, 움직임 가능 여부 같은 **공통 속성**을 기준으로 적용 가능성을 판단한다.

### 조작 상태와 주문 재료를 화면에서도 구분

```text
대상 모드: 조준 대상
현재 주문: <큰> × 3 + <파이어볼>
```

위 예시에서 ‘조준 대상’은 인벤토리 단어가 아니고, `<큰>`과 `<파이어볼>`이 주문 재료다. 표시 형태는 설명용이며 최종 UI 배치를 확정한 것은 아니다.

현재 예시는 **한 효과 단어에 여러 수식 단어를 붙이는 구조**다. 하나의 주문에 여러 효과 단어를 동시에 섞는 규칙은 아직 정하지 않았다. 자유 문장 입력·LLM 해석·음성 인식으로 구조를 바꾸지 않는다.

**참고·경계:** 대상 모드가 세 가지라는 이유로 모든 효과의 세 모드 조합을 자동 구현하지 않는다. 특히 본인/주변에서의 파이어볼 발사와 들기 제어는 효과별 정책이 필요하다. 이전 v0.2의 거리·주변 반경 수치는 확정값으로 승계하지 않는다.

## 03  시전·전달·효과 적용

마법이 발생하고 도달하는 과정이 보여야 한다.

### 효과 단어가 조작과 적용 방식을 결정한다

모든 주문을 ‘클릭하면 지정 대상에 즉시 같은 방식으로 적용’하는 구조로 묶지 않는다. **효과 단어마다 조작법, 시전 속도, 유지 여부, 적용 횟수·지속 방식을 정의**한다.

| 구분할 축 | 의미 |
| --- | --- |
| 입력·시전 | 즉시 발동하는지, 천천히 시전하는지, 시전 상태를 유지하는지. |
| 전달 | 투사체가 이동해 맞는지 등, 마법이 대상까지 도달하는 방식. |
| 효과 적용 | 한 번 적용하는지, 시전 중 계속 제어하거나 지속 적용하는지. |

### 현재 언급된 효과

| 효과 | 사용자 지정 동작 | 미정·주의 |
| --- | --- | --- |
| `<밀치기>` | **즉시 발동하며 한 번 적용**한다. | 구체적인 전달 연출과 명중 판정 방식은 미정. 임의로 시전 준비시간이나 비행 지연을 추가하지 않는다. |
| `<들기>` | 시전이 유지되며 시점 이동에 따라 물체를 지속 제어한다. | 최초 대상 연결 방식, 유지 입력 방식, 본인/주변 모드 동작은 미정. |
| `<파이어볼>` | 투사체를 발사하고, 맞았을 때 효과가 적용되거나 사건이 발생한다. | 시전 준비시간·속도·폭발 여부·수명·추가 충돌 규칙은 미정. |

### 투사체는 연출만 붙이는 장식이 아니다

> 투사체형의 처리 흐름
> **시전 → 투사체 이동 → 실제 충돌 → 맞은 대상과 유효성 확인 → 효과 적용**

투사체가 도달하기 전에 목표에 효과를 미리 적용하고, 뒤늦게 이펙트만 날아가게 하지 않는다. 조준한 대상과 실제 맞은 대상이 다르면 **실제 명중 결과**를 기준으로 적용한다. 이 때문에 다른 플레이어가 맞는 상황도 발생할 수 있다.

눈에 보이는 전달과 실체감이 목적이지만, 모든 효과를 동일한 투사체로 통일하는 것은 아니다. 특히 `<밀치기>`의 즉시 발동과 `<들기>`의 지속 제어를 유지하면서 각 효과의 전달 방식을 정해야 한다.

**참고·경계:** ‘즉시 발동’과 ‘원거리 대상에 지연 없이 적용’은 구분해서 명세한다. 밀치기의 최종 도달·명중 방식은 미정으로 남기며, 이 문서에서 투사체 방식으로 단정하지 않는다.

## 04  들기: 무게와 관성

고정 높이 부양이 아니라, 시점을 따라오는 지속형 물체 제어.

> 사용자 지정 레퍼런스 — **R.E.P.O.의 물체 들기 감각**
> 아래는 사용자가 원하는 구현 특성이다. 참고작의 내부 물리 구현을 검증하거나 그대로 복제하라는 뜻은 아니다.

### 필수 동작

유효한 대상에 `<들기>`를 사용하고 시전이 유지되는 동안 물체를 제어한다. 플레이어가 화면을 돌리면 물체가 바라보는 방향을 따라 움직인다. **시점에 완전히 고정된 물체가 아니라, 무게와 관성을 느낄 수 있는 물체**여야 한다.

| 상황 | 요구하는 반응 |
| --- | --- |
| 물체 무게가 다름 | 무게에 따라 들 수 있는 높이가 달라진다. 모든 물체를 같은 높이·같은 반응으로 띄우지 않는다. |
| 힘보다 너무 무거움 | 힘이 충분하지 않으면 들 수 없다. 실패를 단순 입력 오류와 구분할 수 있어야 한다. |
| 화면을 돌림 | 물체가 즉시 붙어서 회전하지 않고, 관성으로 속도가 붙으며 따라온다. |
| 화면 회전을 멈춤 | 물체가 즉시 정지하지 않고 어느 정도 더 움직인다. 이후 다시 바라보는 쪽으로 돌아온다. |
| 시전이 계속 유지됨 | 한 번 올려두고 끝나는 주문이 아니라, 유지 중 시점 변화에 계속 반응한다. |

### 기존 부양과의 차이

v0.2의 ‘약 2m 위에서 3초간 머무른다’는 `<띄운다>` 설계는 새로운 `<들기>` 요구를 충족하지 않는다. **고정 높이·고정 시간 부양으로 대체하지 않는다.** 기존 부양을 별도 주문으로 남길지는 아직 정하지 않았다.

### 구현 시 지킬 감각과 남아 있는 정책

물체를 카메라에 단순 부착하거나 매 프레임 목표 좌표로 순간이동시키는 방식은 목표 감각과 다르다. 무게·들기 힘·최대 도달 높이·추종 반응·관성·감쇠는 구분해 조정할 수 있어야 한다. 특정 엔진이나 물리 공식은 지정하지 않는다.

**미정:** 버튼을 누르는 동안 유지할지 또는 토글할지, 놓을 때의 속도 처리, 벽·지형과 충돌할 때의 제어, 거리 제한, 여러 사람이 동시에 드는 방식, 본인/주변 모드에서의 동작.

**참고·경계:** 힘을 보강하는 수식어가 들기 힘에 어떻게 연결되는지도 효과별 수치 정의가 필요하다. 공동 들기 힘 합산, 여러 물체 동시 들기, 친구 강제 제어 시간 등을 임의로 확정하지 않는다.

## 05  수식 중첩과 피해 판정

수치 변화는 내부에서, 변화의 체감은 화면과 상호작용에서.

### 수식 단어를 반복해서 붙인다

`<세게>`, `<큰>`처럼 효과 단어의 내부 수치를 강화하는 수식 단어를 추가한다. **보유한 개수만큼 같은 수식을 중첩**할 수 있으며, 각 중첩의 강화가 적용되어야 한다.

```text
<큰> × 3 + <파이어볼>
= <큰>의 강화가 세 번 적용된 파이어볼 발사
```

위 예시는 ‘정확히 3배’나 ‘세제곱 배율’을 뜻하지 않는다. 합산·곱산·감쇠·상한은 미정이다. 강화 계수 자체를 플레이어에게 숫자로 보여주지는 않지만, **보유 개수와 중첩 개수의 표시는 별개**이므로 ×3 같은 표시는 가능하다.

| 수식 | 의도 | 자동으로 확정하지 않을 것 |
| --- | --- | --- |
| `<큰>` | 크기 계열을 강화한다. 예시에서는 파이어볼의 커진 모습을 체감한다. | 피해량·폭발 반경·충돌 크기·질량이 모두 함께 증가한다고 가정하지 않는다. |
| `<세게>` | 힘이나 위력 계열을 강화한다. | 밀치기 힘, 들기 힘, 공격 피해 등 어느 항목을 바꿀지는 효과별로 정한다. |

수집·교환은 유지한다. `<큰>` 3개를 적용하려면 실제로 3개를 보유해야 한다. 넘겨준 단어로 이전 소유자가 새 주문을 계속 강화하는 복제 동작은 허용하지 않는다. 시전마다 단어를 소모하는 규칙은 이번에 추가하지 않는다.

### 같은 마법도 적과 아군에게 다르게 적용

| 명중 대상 | 현재 방향 |
| --- | --- |
| 적 | 수치적인 피해를 받는다. 일반 전투와 보스전에서 사용한다. |
| 다른 플레이어 | 직접 체력을 깎기보다는 **디버프를 주는 방향으로 우선 설계**한다. 아군 마법을 완전히 무효화하는 것은 아니다. |

예: 파이어볼이 친구에게 맞으면 적과 동일한 피해 처리를 그대로 호출하지 않고 아군용 결과를 적용한다. 디버프의 종류·지속시간·중첩·해제 방식은 미정이다. 디버프라는 이름으로 지속 HP 피해를 넣어 체력 감소 방침을 우회하지 않는다.

**참고·경계:** 적의 공격이 플레이어에게 주는 피해, 낙하·충돌·환경의 2차 피해, 자기 시전 피해는 아직 정하지 않았다. 이 방향을 ‘플레이어는 어떤 상황에서도 피해를 받지 않는다’는 규칙으로 확대하지 않는다. 유지형 주문 사용 중 단어 교환에 대한 처리도 별도 결정한다.

## 06  교체 지점과 제작 범위

전체 게임의 방향과, 다음에 검증할 작은 작업을 분리한다.

### v0.2에서 함께 갱신해야 할 부분

| 기존 문서 항목 | 반영 지시 |
| --- | --- |
| §03 문법·대상 단어 | 대상 단어와 해당 슬롯·획득물을 삭제. 대상은 전환 모드로, 주문은 효과+수식으로 변경. |
| §04 작용·조합표 | 고정 3×2 조합표와 고정 시간 부양을 새 요구의 완료 기준으로 쓰지 않는다. 효과별 시전 정책과 들기 규칙으로 갱신. |
| §05 배치·편집·조작 | 대상 단어 3종과 총 6개 토큰 배치를 재사용하지 않는다. 효과·수식 재료와 별도 모드 UI로 변경. |
| §06 제외 범위 | 수식어 제외 방침은 폐기. 전투·상점 등은 전체 방향에 포함하되, 현재 구현 단계에서 제외할지는 별도로 정한다. |
| §07 처리·검증 | 선택 즉시 적용만으로 처리하지 않는다. 실제 명중, 지속 시전, 수식 중첩, 적/아군 결과 분기를 반영. |
| §08 확장 순서 | 대상 단어 교환·범위 단어 발견 중심의 시나리오는 변경. 효과·수식 단어의 발견과 교환을 검증한다. |

### 전체 방향과 현재 작업 범위

모험·전투·보스·휴식·큰 연결형 월드는 **전체 게임의 방향**이다. 이번 메모만으로 이를 한 번에 전부 구현하라고 요청한 것은 아니다. 기존의 작은 2인 테스트 공간은 검증용으로 계속 쓸 수 있으며, 그것을 최종 맵 규모로 확정하지 않는다.

### 소형 검증안 — 제안, 확정 제작량 아님

먼저 기존 프로젝트에서 대상 단어를 제거하고 효과·수식·대상 모드를 분리한다. 작은 멀티플레이 공간에서 `<밀치기>`, `<들기>`, `<파이어볼>`의 서로 다른 동작, `<큰>` 중첩, 단어 교환, 아군 명중 결과를 검증하는 순서를 제안한다.

적 피해 분기는 간단한 시험용 대상에서 확인할 수 있다. 정식 보스·상점·이벤트·대형 월드의 제작은 별도 범위로 잡는다. 음성 반응형 입 구현, 완성형 캐릭터 제작도 레퍼런스 반영 범위와 함께 결정한다.

**참고·경계:** 새 구현안이 기존 안정성을 훼손하지 않도록 단어의 단일 소유권, 낙하·실수 복구, 공동 조작과 상태 동기화 원칙은 유지한다. 다만 이전의 특정 키·면역 시간·힘 수치 등을 최신 사용자 확정값으로 취급하지 않는다.

## 07  미정 사항과 인계 기준

임시 구현값과 확정된 기획을 섞지 않는다.

### 구현 전에 드러내야 할 미정 사항

**대상 모드:** 주변 중심·범위·자신 포함 여부, 효과별 본인/주변 동작. **전달:** 밀치기 전달 방식, 들기 최초 연결, 파이어볼의 상세 충돌. **들기:** 유지 입력·해제·동시 제어. **수식:** 효과별 보정 항목·중첩 공식·상한. **아군:** 디버프 종류·해제·2차 피해. **진행:** 월드 규모·전투 빈도·휴식 배치.

수치나 임시 정책이 구현에 필요하면 **임시 가정으로 명시하고 분리해 조정 가능하게** 둔다. 아직 정하지 않은 핵심 동작을 이미 합의한 요구처럼 보고하지 않는다. 특히 ‘본인+파이어볼’과 ‘주변+들기’는 기존 모드 이름만 보고 동작을 추정하지 않는다.

### 반영 후 확인할 기준

| 번호 | 확인할 결과 |
| --- | --- |
| T1 | 대상 선택은 버튼 전환이다. 대상 단어를 수집·교환·장착하지 않는다. |
| T2 | 투사체형은 명중 시 실제 맞은 대상에 적용한다. 이동 중 선적용하거나 조준 대상을 자동 확정하지 않는다. |
| T3 | 밀치기는 즉시·단발, 들기는 유지·제어로 구별된다. 모든 효과를 같은 시전 코드의 동일 동작으로 만들지 않는다. |
| T4 | 들기는 무게별 높이·힘 부족·회전 추종·멈춘 뒤 관성을 구분해 체감할 수 있다. |
| T5 | `<큰>` 무장착/1개/3개의 결과 차이를 확인한다. 실제 보유량보다 많이 중첩하거나 거래 후 단어가 복제되지 않는다. |
| T6 | 같은 공격이 적에게는 피해, 아군에게는 합의된 디버프 결과로 분기한다. 구체 정책 미정이면 미검증으로 남긴다. |
| T7 | 두 화면에서 투사체 명중·들기·단어 소유·아군 상태가 일치한다. 시각적 관성과 네트워크 불일치를 구분한다. |
